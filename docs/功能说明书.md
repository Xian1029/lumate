# Lumate 项目功能说明书

**文档版本：** 1.0  
**适用版本：** 当前 `main` 分支（提交 `50c569d`）  
**更新时间：** 2026-10-09  
**项目地址：** https://github.com/Xian1029/lumate

## 1. 产品定位

Lumate 是一个本地优先的 AI 学习工作区。用户上传教材或课程资料后，系统将资料解析为可学习的目录、章节内容、笔记、知识点、练习题和复习材料，并根据学习行为持续更新学习进度、推荐内容和复习任务。

系统采用“学习空间 + 可组合区块”的组织方式。每个学习空间对应一套教材或课程资料，学习空间之间的数据和进度相互隔离。

## 2. 主要用户流程

1. 用户进入首页或新建学习空间。
2. 上传 PDF、DOCX、PPTX，或接入 Canvas 课程资料。
3. 系统登记文件、提取文本、识别目录和章节、生成工作区产物。
4. 用户确认创建学习空间；失败资料可重新上传，未确认创建的临时资料会被清理。
5. 用户在学习空间内选择教材、章节或小节，查看学习内容、笔记、知识图谱和练习。
6. 用户完成练习、闪卡和 AI 对话，系统记录掌握度、错题和复习状态。
7. 首页、学习空间和大纲页面使用统一的进度口径展示学习进度。

## 3. 首页与学习空间管理

### 3.1 首页

- 展示所有学习空间，而不是只展示当前一个空间。
- 展示每个空间的名称、教材数量、学习内容数量、已完成数量和学习进度。
- 提供继续学习、新建学习空间和进入空间管理的入口。
- 学习概况聚合多个学习空间的学习时长、题目数、正确率、掌握度和待复习内容。
- 首页进度来源于统一的学习进度计算逻辑，与学习空间、大纲和知识图谱保持一致。

### 3.2 学习空间

- 一个空间可包含多份教材和多个资料文件。
- 支持按教材、章节、小节进行学习范围定位。
- 空间内的笔记、练习、闪卡、知识图谱、错题和学习计划均按空间隔离。
- 空间支持区块布局调整、添加、隐藏、恢复默认和专注/全屏查看。
- 未选择具体可学习小节时，练习和闪卡不展示题目，提示用户先选择章节。

## 4. 资料上传与解析

### 4.1 支持内容

- PDF
- DOCX
- PPTX
- Canvas LMS 课程资料或文件链接

### 4.2 处理阶段

上传流程包含以下阶段：

1. 登记上传内容
2. 提取文本
3. 识别或生成目录
4. 分类资料
5. 构建工作区产物
6. 构建语义索引

### 4.3 有目录资料

系统优先保留原始目录和章节层级，在章节节点上生成学习内容、笔记、题目、闪卡和知识点关联。教材原有顺序作为推荐学习路径的重要依据。

### 4.4 无目录资料

当资料没有可靠目录时，系统根据内容进行语义分段：

- 识别标题、主题句和内容边界。
- 按主题和语义连续性切分学习单元。
- 为分段生成有条理的标题和层级。
- 避免把目录、版权页、封面等信息误当成学习内容。
- 分段结果仍可用于笔记、练习、闪卡、知识图谱和推荐路径。

### 4.5 失败处理和清理规则

- 单个文件解析失败时，显示失败原因并允许重新上传。
- 未完成解析的资料不会发布为可用学习内容。
- 用户未确认创建学习空间时，临时上传资料和中间产物应清除。
- 用户确认创建后，成功解析的资料进入学习空间；失败资料保留失败状态，供用户重新处理。
- 解析日志用于展示当前阶段、失败文件和可重试操作。

## 5. 教材目录与学习内容

- 目录支持教材、章节、小节层级浏览。
- 点击具体小节后，右侧内容、笔记、练习、闪卡和图谱切换到该小节范围。
- 点击前言、目录或非学习节点时，不生成练习和闪卡。
- 没有选择小节时，笔记使用面向 K12 用户的引导提示，而不是误导性内容。
- 课程大纲进度与空间总进度使用同一组已完成内容和可学习内容计算。

## 6. 知识图谱

### 6.1 图谱生成

- 图谱由当前学习空间上传的全部教材内容生成。
- 节点来自语义知识点，不直接把章节号作为知识点名称。
- 节点之间记录前置学习、相关概念和教材学习顺序关系。
- 多本教材的知识点合并到同一空间图谱，并保留来源教材标记。

### 6.2 展示规则

- 当前教材相关节点使用特殊标记。
- 与当前教材相关的推荐路径也使用对应标记。
- 节点文字自动换行，避免超出卡片边界。
- 节点较少时使用自适应布局，避免画布过度留白。
- 节点较多时使用可滚动、自适应画布，保证节点和关系可查看。
- 点击节点显示明确说明卡片；点击空白区域关闭说明卡片。

### 6.3 推荐学习路径

推荐路径综合以下信息：

- 教材中的先后顺序。
- 知识图谱中的前置关系。
- 用户当前掌握度。
- 错题和复习需求。
- 当前选择的教材和小节。

只有当前置内容满足解锁条件时，后续阶段才可标记为已解锁；未完成前置阶段时不得提前解锁。

## 7. AI 笔记与 AI 导师

### 7.1 AI 笔记

- 根据当前教材和小节生成结构化学习笔记。
- 笔记内容与教材章节绑定，避免跨章节混入内容。
- 支持重点、概念、例题、易错点和复习提示等结构。
- 生成结果需经过文本清理，避免英文标识、内部 ID、乱码或原始协议字段直接展示。

### 7.2 AI 导师

- 基于当前学习空间资料回答问题。
- 支持苏格拉底式提问，引导用户先解释、比较、举例和验证，而不是直接给结论。
- 可根据错题、掌握度和前置知识生成学习建议。
- AI 提醒必须使用中文和可读的知识点名称，不能出现 `unknown`、内部事件名或原始英文提示。
- 支持来源上下文和当前章节上下文。

## 8. 练习与测验

### 8.1 题目生成

- 题目根据当前选中的教材小节和学习内容生成。
- 单次生成题目不超过 15 道。
- 生成题目按批次保存，批次用于恢复未完成练习和区分新旧题组。
- “换一组新题”使用去重规则，避免与历史题目重复。
- 完成一组题后，再次进入练习会准备新的题组，而不是恢复已完成题组。

### 8.2 支持题型

- 选择题
- 多选题
- 判断题
- 填空题
- 简答题
- 匹配题
- 编程题

### 8.3 答题流程

- 用户提交答案后，系统返回判定、正确答案、解析、匹配类型和必要的复习提示。
- 同一题提交过程具备幂等保护，避免重复点击造成重复记录。
- 全屏和缩小模式共享同一题目状态、进度和答案记录。
- 退出测验后，已完成题组不作为下一次练习恢复对象。
- 新题生成期间显示明确状态；请求失败时快速结束并允许重试，不无限停留在加载状态。

### 8.4 判题规则

判题采用统一后端规则，前端不自行决定正确与否，主要顺序为：

1. 精确匹配
2. 规范化匹配（全角符号、数学符号、空白和同义表达）
3. 数值等价和单位校验
4. 结构化答案匹配
5. 语义判定
6. 无法确定时进入待复核状态，不直接惩罚用户

针对 K12 数学题，系统特别处理：

- 正负号、相反数和温度正负关系。
- 向左/向右、增加/减少等方向与符号关系。
- “先指出原答案错误，再给出正确答案”的修正型作答。
- 带姓名或对象的数量分类题。
- 数轴位置、原点、正半轴、负半轴等结构化答案。
- 合理的单位、空格和标点差异。

## 9. 闪卡与间隔复习

- 闪卡与当前选择的小节绑定。
- 未选择具体小节时不显示闪卡内容。
- 支持翻面、知道了/需要复习等反馈。
- 使用 FSRS 间隔重复调度，结合掌握度和复习时间安排下一次复习。
- 全屏和缩小模式使用同一份闪卡状态，进度保持一致。

## 10. 错题、复盘与盲点

### 10.1 错题记录

- 错题按题目唯一标识归并，同一道题不会因为多次作答无限重复显示。
- 记录错误次数、复盘次数、错误分类、诊断和掌握状态。
- 复盘中重新答对后，错题显示“已解决”，不再重复展开相同历史内容。

### 10.2 错题分析

- 不只罗列题目，而是按知识点、错误类型、符号/概念/步骤问题进行归因。
- 显示用户答案、正确答案、解析、错误次数和复盘结果。
- 已解决内容使用完成样式，不显示为未完成进度。
- 进度条、序号和解决状态使用统一状态语义。

### 10.3 盲点

- 同一题只显示一次。
- 与复盘记录关联，复盘解决后标记为已解决。
- 盲点内容来自真实作答记录和知识点诊断，不使用无依据的重复推荐。

## 11. 学习计划

- 支持手动创建学习计划。
- 支持 AI 创建学习计划。
- 用户可多选本次要完成的章节内容。
- 目标日期默认当天；用户不修改时，任务默认安排在当天。
- 每天学习时长以分钟填写或选择。
- 计划任务只围绕用户选择的章节生成。
- 支持计划草稿、确认、编辑、提交和任务追踪。

## 12. 学习进度与数据统计

- 统一统计学习内容完成数、题目完成数、正确率、学习时长、掌握度和复习状态。
- 首页学习概况支持多个学习空间聚合展示。
- 学习空间、大纲、知识图谱、复盘和首页使用一致的进度计算口径。
- 掌握度时间线展示掌握度变化趋势，避免重复和冗余信息。
- 支持错题分析、掌握度、学习活动和预测等统计视图。

## 13. 工作区区块

当前区块系统支持以下主要区块：

- 章节目录
- 笔记
- 测验
- 闪卡
- 进度
- 知识图谱
- 学习计划
- 复盘
- 错题
- AI 洞察/学习提醒
- 学习统计
- 课程资料或相关辅助区块

区块支持固定、隐藏、添加、恢复默认、调整尺寸和专注/全屏查看。系统区块和用户添加区块有不同的保护规则，必要的章节目录和笔记不会被误删。

## 14. LLM 与外部服务配置

### 14.1 DeepSeek

在项目根目录 `.env` 配置：

```env
LLM_PROVIDER=deepseek
LLM_MODEL=deepseek-chat
DEEPSEEK_API_KEY=sk-...
```

DeepSeek 使用 OpenAI 兼容接口 `https://api.deepseek.com/v1`。

### 14.2 支持的模型服务

- Ollama
- OpenAI
- Anthropic
- DeepSeek
- OpenRouter
- Gemini
- Groq
- vLLM
- LM Studio
- Text Generation WebUI
- 自定义 OpenAI 兼容服务

### 14.3 安全要求

- API key 只放在后端环境变量，不放入前端代码。
- 本地开发默认可关闭认证；生产或联网部署必须启用认证并配置 JWT secret。
- 不要将 `.env`、上传文件、数据库文件或 API key 提交到 Git。

## 15. 启动与运行

### 15.1 固定端口启动

```bash
./start.sh
```

启动脚本会：

1. 停止占用 8001 和 3003 的旧服务。
2. 构建前端生产版本。
3. 启动 FastAPI 后端。
4. 等待后端健康检查通过。
5. 启动 Next.js 前端。
6. 等待前端响应成功。

访问地址：

- 前端：`http://localhost:3003`
- 后端 API：`http://127.0.0.1:8001/api`
- API 文档：`http://127.0.0.1:8001/docs`

### 15.2 停止服务

```bash
./stop.sh
```

### 15.3 常用验证

```bash
curl http://127.0.0.1:8001/api/health/live
cd apps/web && npm run build
```

## 16. 技术架构概览

- **前端：** Next.js、React、TypeScript、Tailwind CSS、Zustand。
- **后端：** FastAPI、Pydantic、SQLAlchemy、Alembic。
- **数据：** 本地优先数据库和上传目录。
- **AI：** 多提供商 LLM 路由、健康检查、失败降级和请求超时。
- **学习科学：** FSRS、掌握度追踪、知识图谱、前置关系和自适应练习。
- **检索：** 文本/向量索引与课程资料上下文检索。
- **测试：** Python 单元测试、Vitest 前端测试、生产构建和 Playwright E2E。

## 17. 当前使用边界

- AI 生成质量受资料文本质量、目录质量和当前 LLM 服务可用性影响。
- 没有选择具体学习小节时，练习和闪卡不会生成无上下文题目。
- LLM 服务不可用时，资料浏览、已有内容和基础进度仍可使用，但新题、AI 笔记或 AI 对话可能无法生成。
- 本地开发模式的认证配置不适合直接暴露到公网。
